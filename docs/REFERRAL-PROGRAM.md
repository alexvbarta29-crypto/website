# Customer referral program

A self-contained "Give $25, Get $50" referral system that lives on the
existing static site and runs on the same Netlify stack as the quote form
(Netlify Functions + Rotor CRM), with Netlify Blobs as its own small
database. No third-party referral SaaS, no accounts or passwords for
customers.

## The offer (single source of truth)

| Who                       | What they get                                        |
|---------------------------|------------------------------------------------------|
| The friend being referred | **$25 off** their first service                      |
| The customer who referred | **$50 account credit** *or* a **$25 gift card**, per friend who books (their choice) |

Amounts live in exactly two places that must be kept in sync:

- `build/sitedata.py` → `REFERRAL` (drives every number printed on the pages)
- `netlify/lib/referral-config.mjs` → `REWARDS` (drives API responses, SMS
  text, and CRM notes)

## How it works, end to end

1. **The owner texts a customer** the program link
   `https://www.bartawindowwashing.com/refer.html` ("Want $50 off? Refer a
   friend.").
2. **The customer fills in the form** on `refer.html`: their own name, phone,
   optional email, who they're referring (name + phone required; email,
   address, and a note optional; up to 10 friends at once), and which
   reward they want (credit or gift card). They confirm they have the
   friend's permission to share their contact details.
3. **The site stores the referral** (Netlify Blobs), **creates a lead in
   Rotor** for each friend (tag `Referral`, source `Referral program`,
   notes naming the referrer and the code), and, when SMS is enabled,
   **texts the friend, the referrer, and/or the office** (see
   `REFERRAL_SMS_MODE`). The customer sees a success screen with their
   share code, a copy-able share link, one-tap "Text a friend" / "Email"
   buttons, and a private tracking link.
4. **The office reaches out to the friend** ("Hi Jane, Alex referred you,
   here's $25 off") — either automatically via Twilio or manually from the
   admin dashboard, which has one-tap `sms:` links with the message
   pre-written.
5. **The friend books.** They can use the short link `/r/CODE`
   (→ `referred.html`), which explains the $25 and sends them to the quote
   wizard with the promo code pre-filled. When a quote request arrives with
   a referral code, or from a phone number that was referred, the lead is
   tagged `Referral` in Rotor and the referral moves to *Quote requested*
   automatically.
6. **The office marks the referral Booked, then issues the reward** in the
   admin dashboard (`$50 credit` or `$25 gift card`). The referrer's private
   tracking page updates immediately.

## Pages

| URL | Purpose | Indexed |
|-----|---------|---------|
| `/refer.html` | Program page: offer, how it works, the referral form, FAQ. With `?t=TOKEN` it also shows the referrer's private dashboard (their referrals + statuses + rewards) and lets them add more friends. | yes |
| `/referred.html?code=CODE` (short: `/r/CODE`) | Friend landing: "Alex sent you $25 off", CTA to the quote wizard with the code pre-filled, call button. Unknown code → generic version of the page. | no |
| `/get-quote.html?promo=CODE&src=referral` | Existing quote wizard; `promo` pre-fills the promo-code field and `src=referral` pre-selects "Family/Friend" as the source. | yes (existing) |
| `/admin/referrals.html` | Office dashboard, protected by `REFERRAL_ADMIN_KEY`. | no (`noindex` + `robots.txt` Disallow) |

All pages are generated by `build/build.py` like the rest of the site
(`python3 build/build.py`):

- `build/referral_pages.py` → `referral_page(depth)` and `referred_page(depth)`
- `build/referral_admin_page.py` → `referral_admin_page(depth)`
- Page-specific styling/behaviour: `assets/css/referral.css`,
  `assets/js/referral.js`, `assets/css/referral-admin.css`,
  `assets/js/referral-admin.js` (minified to `*.min.*` by the build and
  cache-busted with `?v=` like `styles.css` / `main.js`).

## Environment variables (Netlify → Site configuration → Environment variables)

| Variable | Required | Purpose |
|----------|----------|---------|
| `ROTOR_API_KEY` | yes (already set for the quote form) | Creates referred friends as leads in Rotor. |
| `REFERRAL_ADMIN_KEY` | yes, for the dashboard | Long random secret (32+ chars) the office enters on `/admin/referrals.html`. Without it the admin API returns 503 and the dashboard says so. |
| `REFERRAL_SMS_MODE` | no (default `off`) | `off` = no automatic texts (office texts manually from the dashboard). `office` = text the office number on every new referral. `all` = also text the friend and the referrer. |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` | only when SMS mode ≠ `off` | Twilio credentials; `TWILIO_FROM` is the sending number in E.164 (`+17633143400`) or a Messaging Service SID (`MG…`). |
| `REFERRAL_OFFICE_PHONE` | only for SMS modes `office`/`all` | Where new-referral alerts are texted (E.164). |
| `SITE_URL` | no (default `https://www.bartawindowwashing.com`) | Base for links in texts and API responses. |

Netlify Blobs needs no configuration; it is available to every Netlify
Function automatically. Nothing referral-related works on the GitHub Pages
preview (no functions), where the forms show the honest call-us fallback.

> **Texting referred friends.** Mode `all` sends a text to a person who has
> not themselves opted in, on the strength of their friend's confirmation
> that they have permission. Keep the message to a single informational
> text with an opt-out line (the templates below do), or leave the mode at
> `off`/`office` and text from the dashboard by hand. Have this reviewed
> against TCPA/CTIA guidance before turning `all` on.

## Data model (Netlify Blobs, store `referrals`)

All records are JSON. Timestamps are ISO-8601 UTC strings. Phone numbers
are stored both as typed (`phone`) and normalized to 10 digits
(`phone_digits`, US only, leading `1` stripped); the digits are the
identity everywhere.

```
referrer/{referrer_id}         referrer_id = phone_digits
  { id, code, token, first_name, last_name, phone, phone_digits, email,
    reward_pref: "credit" | "giftcard", consent_at, source_page,
    created_at, updated_at }

code/{CODE}                    -> { referrer_id }        public share code, e.g. BARTA-7K3XQ
token/{TOKEN}                  -> { referrer_id }        private dashboard token, 24 chars, base32

referral/{referral_id}         referral_id = "r_" + base36 time + 6 random chars
  { id, referrer_id, code, referrer_name, referrer_phone,
    first_name, last_name, phone, phone_digits, email, address, note,
    office_note,
    status: "new" | "contacted" | "quoted" | "booked" | "rewarded" | "declined",
    history: [ { status, at, by: "system" | "office" | "lead-form", note } ],
    reward: null | { type: "credit" | "giftcard", amount, issued_at, note },
    duplicate_of: null | referral_id,
    rotor: { delivered: bool, status: number | null, at },
    sms: { friend: bool, referrer: bool, office: bool },
    quote_requested_at: null | ISO,
    created_at, updated_at }

idx/referrer/{referrer_id}/{referral_id}  -> { id }     lists a referrer's referrals
idx/phone/{friend_phone_digits}            -> { id }     first referral of this friend (dedupe + lead matching)
```

Codes use the alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no 0/O/1/I),
five characters after the `BARTA-` prefix. Lookups are case-insensitive.

### Statuses

| Status | Meaning | Set by |
|--------|---------|--------|
| `new` | Referral received; office has not reached out yet. | system |
| `contacted` | Office has texted/called the friend. | office |
| `quoted` | The friend requested a quote (via the site with the code or a matching phone). | lead form (automatic) or office |
| `booked` | The friend booked/completed their first service; reward is owed. | office |
| `rewarded` | Reward issued to the referrer (`reward` filled in). | office (`issue_reward`) |
| `declined` | Not eligible / not interested / duplicate. | office |

The office can move a referral to any status at any time; `rewarded` is
set through `issue_reward` so the reward details are always recorded.

### Duplicates

A friend phone number that already has a referral (from anyone) is
accepted but flagged: the new record gets `duplicate_of` set to the first
referral's id and status `new`; it is **not** sent to Rotor again and no
friend text goes out. The referrer sees it as a normal "Sent" entry; the
office sees a "Duplicate" badge and decides. A referrer can never refer
their own phone number.

## API (Netlify Functions, same origin)

All responses are JSON with `Cache-Control: no-store`. Errors are
`{ "ok": false, "error": "<human readable>", "field": "<optional dotted path>" }`.

### `POST /api/referral` — submit referrals (public)

```json
{
  "referrer": { "first_name": "Alex", "last_name": "Barta", "phone": "(763) 555-0100",
                "email": "alex@example.com", "reward_pref": "credit" },
  "friends": [
    { "first_name": "Jane", "last_name": "Doe", "phone": "763-555-0101",
      "email": "", "address": "123 Main St, Delano, MN 55328", "note": "Neighbor, big house" }
  ],
  "consent": true,
  "page": "/refer.html",
  "token": "optional — when adding friends from an existing private dashboard"
}
```

Rules: referrer first name + valid 10-digit US phone required; `reward_pref`
required (`credit`/`giftcard`); `consent` must be `true`; 1–10 friends; each
friend needs a first name and a valid phone; a friend's phone can't equal
the referrer's; duplicates within one submission collapse to one. Field
caps: names 60, email 120, address 200, note 500 chars; longer values are
rejected with `400` and the field path rather than silently cut.

Success `200`:

```json
{
  "ok": true,
  "code": "BARTA-7K3XQ",
  "token": "K7Q2M9X4P8W3N6R5T2Y7V4B9",
  "share_url": "https://www.bartawindowwashing.com/r/BARTA-7K3XQ",
  "status_url": "https://www.bartawindowwashing.com/refer.html?t=K7Q2M9X4P8W3N6R5T2Y7V4B9",
  "referrer": { "first_name": "Alex", "reward_pref": "credit" },
  "friends": [ { "id": "r_m1abc2xyz123", "first_name": "Jane", "status": "new", "duplicate": false } ],
  "stored": true,
  "delivered": true
}
```

`stored: false` means Netlify Blobs was unavailable (referrals still went to
Rotor; tracking link will not work). `delivered: false` means Rotor
rejected/was unreachable for at least one friend (they are still stored and
show in the dashboard). Only when **both** fail does the request return
`502` so the page shows the call-us fallback. An existing referrer (same
phone) keeps their existing code/token; `reward_pref` is updated to the
latest choice.

### `GET /api/referral?t=TOKEN` — private dashboard (referrer)

```json
{
  "ok": true,
  "referrer": { "first_name": "Alex", "last_name": "Barta", "phone": "(763) 555-0100",
                "email": "alex@example.com", "reward_pref": "credit", "code": "BARTA-7K3XQ" },
  "share_url": "https://www.bartawindowwashing.com/r/BARTA-7K3XQ",
  "totals": { "referred": 3, "booked": 1, "rewarded": 1, "pending": 1,
              "credit_earned": 50, "gift_cards_earned": 0 },
  "referrals": [
    { "id": "r_…", "friend_name": "Jane D.", "status": "rewarded",
      "created_at": "…", "updated_at": "…",
      "reward": { "type": "credit", "amount": 50, "issued_at": "…" } }
  ]
}
```

`totals.pending` counts `new`/`contacted`/`quoted`; `booked` counts
`booked` + `rewarded`. Unknown token → `404`. Every read endpoint (this one,
the code lookup, and the admin API) answers `503` when Netlify Blobs itself
is unavailable, so the pages can say "try again in a minute" instead of
pretending there is nothing to show.

### `GET /api/referral?code=CODE` — public share-code lookup (friend landing)

```json
{ "ok": true, "code": "BARTA-7K3XQ", "referrer_first_name": "Alex",
  "friend_discount": 25, "referrer_credit": 50, "referrer_gift_card": 25 }
```

Deliberately exposes only the referrer's first name. Unknown code → `404`.

### Admin — `/api/referral/admin`

Every request carries `Authorization: Bearer <REFERRAL_ADMIN_KEY>`.
Wrong/missing key → `401`; key not configured on the server → `503`.

`GET /api/referral/admin` (optional `?status=new&q=jane`):

```json
{
  "ok": true,
  "stats": { "total": 12, "by_status": { "new": 3, "contacted": 2, "quoted": 1, "booked": 2, "rewarded": 3, "declined": 1 },
             "rewards_owed": 2, "credit_issued": 100, "gift_cards_issued": 1 },
  "referrals": [ { …full referral record… } ],
  "referrers": [ { "id": "7635550100", "code": "BARTA-7K3XQ", "first_name": "Alex", "last_name": "Barta",
                   "phone": "(763) 555-0100", "email": "…", "reward_pref": "credit", "created_at": "…",
                   "status_url": "https://www.bartawindowwashing.com/refer.html?t=…",
                   "referred": 3, "booked": 1, "rewarded": 1 } ]
}
```

Newest referrals first. `?status=` and `?q=` narrow only `referrals`;
`stats` stay global and `referrers` is always the full list (each with a
ready-made `status_url` so the office can resend a customer's tracking
link; the raw token is never returned). `GET /api/referral/admin?format=csv`
returns `text/csv` of every referral (filters ignored, one row each: id,
dates, status, friend and referrer details, code, reward, Rotor delivery)
for a spreadsheet; cells that start with `=`, `+`, `-` or `@` are
neutralized so a spreadsheet can't run them as formulas.

`POST /api/referral/admin` with one of:

```json
{ "action": "set_status",  "id": "r_…", "status": "contacted", "note": "Left voicemail" }
{ "action": "issue_reward", "id": "r_…", "reward_type": "credit", "note": "Applied in Rotor 9/3" }
{ "action": "set_note",     "id": "r_…", "note": "Office-only note" }
{ "action": "set_reward_pref", "referrer_id": "7635550100", "reward_pref": "giftcard" }
{ "action": "delete",       "id": "r_…" }
```

Each returns `{ "ok": true, "referral": {…} }` (or `{ "ok": true, "referrer": {…} }`,
or `{ "ok": true, "deleted": "r_…" }`). `issue_reward` sets `status:
"rewarded"` and `reward: { type, amount, issued_at, note }` (amount from
`REWARDS`; `reward_type` defaults to the referrer's `reward_pref`). Every
status change appends to `history` with `by: "office"`. Guard rails:
`issue_reward` on a referral that is already `rewarded` answers `409` (move
it back to Booked first if the reward really must be re-issued);
`set_status` to `rewarded` answers `400` (rewards go through `issue_reward`
so the details are always recorded); moving a rewarded referral to any
other status clears its `reward` so totals stay honest. Ids must look like
`r_…` and `referrer_id` must be a 10-digit phone; anything else is `404`.

### Quote form integration (`/api/lead`)

`netlify/functions/lead.mjs` gains one best-effort step (wrapped in
try/catch with a 1.5 s timeout, so it can never break or noticeably delay
a quote request): if `promo_code` looks like a referral code and exists, or
the lead's phone matches `idx/phone/…`, the Rotor payload gets the tag
`Referral` and a notes line `Referral code: BARTA-7K3XQ (referred by Alex
Barta)`, and the matched referral moves from `new`/`contacted` to `quoted`
with `quote_requested_at` set (history entry `by: "lead-form"`).

**Share-link arrivals.** A friend the referrer never listed on `refer.html`
(they were simply sent the `/r/CODE` link or told the code) has no record
yet. When such a quote request carries a valid code and a phone number, the
hook creates the referral on the spot under that referrer, already at
`quoted`, with the name / email / address from the quote form and
`rotor.delivered: true` (the quote form is what delivered them). It shows
up in the dashboard and on the referrer's tracking page like any other
referral, and a later listing of the same phone is treated as a duplicate.
A customer typing their own code into their own quote request is ignored
(no tag, no record).

## Text message templates

Used by the Twilio sender and, verbatim, by the dashboard's one-tap `sms:`
links (so manual and automatic texts read the same).

- **Friend:** `Hi {friend_first}! {referrer_first} {referrer_last_initial}. referred you to Barta Window Washing, so your first service is $25 off. Claim it here: {share_url} or call (763) 314-3400. Reply STOP to opt out.`
- **Referrer (confirmation):** `Thanks for referring {n} friend(s) to Barta Window Washing! You earn a $50 credit (or a $25 gift card) for each one who books. Track your referrals: {status_url}`
- **Referrer (reward issued, manual from dashboard):** `Great news from Barta Window Washing: {friend_first} booked, so your {reward} is ready. Thanks for spreading the word!`
- **Office alert:** `New referral: {referrer_name} ({referrer_phone}) referred {friend_name} ({friend_phone}). Code {code}. {site}/admin/referrals.html`

When the referrer gave no last name the friend text reads `Alex referred
you…` (no dangling initial). The customer's own "Text a friend" / "Email a
friend" buttons on `refer.html` send a shorter personal note from their
own phone (`Hi! Alex referred you to Barta Window Washing, so your first
service is $25 off. Claim it here: {share_url}`), since a text from a
friend should not carry a business opt-out line.

## Admin dashboard (`/admin/referrals.html`)

Phone-friendly, app-like page (no site nav). Enter the admin key once
(kept in `sessionStorage`). Shows: stat tiles (New, Contacted, Quote
requested, Booked / rewards owed, Rewards issued), status filter tabs, a
search box (name / phone / code), and a card per referral with friend and
referrer details, created date, status, a status selector, "Text friend" /
"Text referrer" / "Call" one-tap links, an office note, and an **Issue
reward** action ($50 credit or $25 gift card). A Referrers view lists each
customer with referred / booked / rewarded counts and their reward
preference. **Export CSV** downloads everything. A `401` sends you back to
the key screen.

## Testing

```bash
npm install          # once: installs @netlify/blobs for the functions
npm test             # node --test "tests/**/*.test.mjs"  (all functions are unit-tested with a mocked store + fetch)
python3 build/build.py   # regenerate pages after editing build/*.py, sitedata.py, or the css/js
```

No test ever talks to Rotor, Twilio, or Netlify Blobs: `globalThis.fetch`
is stubbed and the store is an in-memory Map.

## Launch checklist

1. Set `REFERRAL_ADMIN_KEY` in Netlify (generate with `openssl rand -base64 32`). Redeploy.
2. Open `/admin/referrals.html`, enter the key, confirm the empty dashboard loads.
3. Submit a test referral on `/refer.html` (use your own phone as the friend). Confirm it shows in the dashboard and as a lead tagged `Referral` in Rotor.
4. Open the tracking link from the success screen; confirm the referral shows as "Sent". Mark it Booked, then Issue reward; confirm the tracking page updates.
5. Optional: add Twilio variables and set `REFERRAL_SMS_MODE=office` to get an alert text per referral; move to `all` only after the compliance note above.
6. Text your customers the link: `https://www.bartawindowwashing.com/refer.html`.
