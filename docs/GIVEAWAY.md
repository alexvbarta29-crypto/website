# Holiday Lights Giveaway (2026)

A referral-powered giveaway that lives at **bartawindowwashing.com/giveaway**,
built on the same Netlify stack as the quote form and the referral program
(Netlify Functions + Netlify Blobs + Rotor CRM + optional Twilio).

## The offer (single source of truth)

| What | Value |
|------|-------|
| Prize | 2 drawn winners, each a professional Christmas light install, ARV up to $1,500 |
| "Friend wins, you both win" | If a drawn winner entered through someone's share link, that person also wins an install (so up to 4 installs) |
| Entries | 1 per household, +1 for every eligible friend who enters through your link |
| Who | 18+, home within 17 straight-line miles of Delano. The number is never shown to visitors (owner's call); the page and rules point to the circle on the map |
| Entries close | Thu Nov 5, 2026, 11:59 PM Central |
| Drawing | Fri Nov 6, 2026, 6:00 PM Central (film it / go live on Facebook) |
| Non-winners | $250 off a 2026 light install, claim within 72 hours (by Mon Nov 9, 6 PM) |

Dates and amounts live in two places that must match:
`build/sitedata.py` → `GIVEAWAY` (pages, official rules) and
`netlify/lib/giveaway-config.mjs` → `GIVEAWAY` / `DATES` / `SMS` (API, texts, Rotor notes).

## Rotor tags (what each one means)

| Tag | Added when | Use it for |
|-----|-----------|------------|
| `Giveaway 2026` | Every entry | Texts 1 (nudge) and 2 (drawing tonight) |
| `Giveaway - Coupon Opt-In` | Entrant ticked the optional $250-coupon box | Texts 3, 4, 5 (coupon + follow-ups) |
| `Giveaway - Winner` | Automatically when the dashboard draws (and for an alternate) | Leave these people OUT of texts 3, 4, 5 |
| `Giveaway - Coupon Claimed` (+ `Christmas Lights`) | Entrant claimed on their entries page | A real light lead: send the quote |
| `Giveaway - Out of Area` | Outside the circle, asked for a quote anyway (source "Website quote form") | Normal quote follow-up |

Entering does NOT add `Christmas Lights`: that tag is how real light leads
are found, and a claim adds it. Each new entrant's notes say "$250 coupon
texts: YES, opted in" or "no", plus their share link and who invited them.
A YES reply to the coupon text arrives in the Rotor inbox; add
`Giveaway - Coupon Claimed` to that lead by hand (or ask Claude to). Tags are
only ever added (Rotor merges them); if a winner is replaced, remove
`Giveaway - Winner` from that lead by hand.

### Existing leads are never overwritten

Rotor upserts by phone, so someone who is already a lead (a quote request,
a Meta lead) would have their name, source and notes replaced by a plain
upsert. Every giveaway write (`netlify/lib/giveaway-rotor.mjs`) goes in two
steps instead: (1) the phone alone, which finds or creates the lead;
(2) by phone again (never by id, which blanks fields it isn't sent), the
tags, plus name, address, source and notes if Rotor just created
the lead, or only notes appended under theirs if it already existed. The
tags always arrive in step 2, an update, so Rotor's "Tag added" workflows
fire for new and existing leads alike. The dashboard card says
"in Rotor (already a lead, only tagged)" for existing ones.

### Rotor workflows (Marketing → Workflows)

Giveaway people sit in their own holding pipelines (one stage each, never
moved) and stay out of the sales pipeline:

| # | Trigger | Action |
|---|---------|--------|
| 1 | Lead created, source filter = Website quote form, Meta Ads, Referral, Referral Program (keep one such workflow; there are two) | Add to Pipeline → New Lead - No Estimate Yet (existing) |
| 2 | Lead → Tag added → `Giveaway 2026` | Add to Pipeline → **Giveaway - Entrants** |
| 3 | Lead → Tag added → `Giveaway - Winner` | Add to Pipeline → **Giveaway - Winners**; Send Notification to the owner |
| 4 | Lead → Tag added → `Giveaway - Coupon Claimed` | Add to Pipeline → **Giveaway - $250 Claimed**; Create Task "Send Christmas light quote"; Send Notification |
| 5 (optional) | Lead → Contact replied, Conditional Split: has tag `Giveaway - Coupon Opt-In` | Send Notification "Giveaway reply: check for YES" |

Out-of-area quote requests arrive as source "Website quote form" and go
through workflow 1 like any quote. The coupon opt-in needs no pipeline: the
tag is what texts 3-5 filter on.

## The flow (maps to the playbook)

1. **Entry** (`POST /api/giveaway`): name, mobile, address, texting consent.
   The address is checked on the spot: coordinates from the autocomplete pick
   (≤ 20 mi), else a server-side geocode, else the city list. Outside the area
   → the visitor is told plainly and offered a free quote anyway (a Rotor lead
   tagged `Giveaway - Out of Area`). Couldn't tell → accepted and flagged
   "Check address" on the dashboard.
2. **Share link** shows on screen the moment they submit (copy, share sheet,
   text, Facebook). Every entry becomes a Rotor lead tagged `Giveaway 2026`
   with their share link and who invited them in the notes (an existing lead
   is only tagged, with the notes appended).
3. **Nudge** (Tue Nov 3): dashboard → Texts → "3-day nudge" sends each person
   their real entry count and link.
4. **Drawing** (Fri Nov 6): dashboard → Drawing. Weighted random draw
   (`crypto.randomInt`), bonus winners added automatically, "Replace (no
   response)" draws an alternate. Call and text the winners from their cards.
5. **Coupon** (within an hour): dashboard → "Coupon to everyone who didn't win".
   The text links to their page, where one tap claims it.
6. **YES flow**: a claim adds `Giveaway - Coupon Claimed` to the Rotor lead, with
   service type Christmas Light Installation and "Send the quote!" in the notes,
   and (SMS mode on) texts the office. Name, phone and address are already there.
7. **Follow-ups** (Sat Nov 7, Sun Nov 8): the 24h and 48h texts go only to
   people who got the coupon text and haven't claimed.

Every broadcast skips anyone already sent that text, so a batch that stops
can be re-run. Without Twilio, **Export CSV** gives each person's own nudge and
coupon text, and every entrant row has one-tap "Text:" links.

## Environment variables

| Variable | Needed | Purpose |
|----------|--------|---------|
| `ROTOR_API_KEY` | already set | Leads |
| `REFERRAL_ADMIN_KEY` | already set (or `GIVEAWAY_ADMIN_KEY`) | Dashboard |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` | for automatic texts | Broadcast buttons |
| `GIVEAWAY_SMS_MODE` | optional, default `off` | `on` = welcome text on entry + office alert on each coupon claim |
| `REFERRAL_OFFICE_PHONE` | for the claim alert | Office's mobile, E.164 |

## Data (Netlify Blobs store `giveaway`)

```
entrant/{phone_digits}   { id, code, token, first_name, last_name, phone, address{street,city,state,zip,lat,lng,verified},
                           household, area{ok,method,miles}, referred_by{id,code,name}|null, consent_at,
                           rotor, sms{welcome,nudge,coupon,followup24,followup48,<t>_failed}, coupon{claimed_at}|null,
                           disqualified?, sms_opt_out?, office_note, created_at, updated_at }
code/{LIGHTS-XXXXX} -> {id}     token/{TOKEN} -> {id}     household/{key} -> {id}
idx/ref/{referrer_id}/{entrant_id}     outside/{phone_digits}     draw/result
```

## Before launch

1. Have a lawyer read `/giveaway/rules` once (prize description, the up-to-4
   prize total, the texting consent).
2. Test on the deploy preview: enter with your phone, enter a second phone via
   the share link, check the count, draw early from the dashboard, claim the
   coupon, check Rotor. Then **Reset → Delete all giveaway data** and delete the
   test leads in Rotor.
3. Merge. Post the video everywhere, all pointing at `/giveaway`.

Tests: `npm test` (tests/giveaway.test.mjs).
