# Barta referral app ("Give $25, Get $50")

A small standalone web app for the customer referral program: its own
repository, its own site and its own link (for example
`refer.bartawindowwashing.com`), completely separate from the main website.
It runs on Netlify (static pages + Netlify Functions + Netlify Blobs as its
small database) and creates leads in Rotor CRM like the website's quote form
does.

## The offer (single source of truth)

| Who                       | What they get                                        |
|---------------------------|------------------------------------------------------|
| The friend being referred | **$25 off** their first service                      |
| The customer who referred | **$50 account credit** *or* a **$25 gift card**, per friend who books (their choice) |

Amounts live in exactly two places that must be kept in sync:

- `build/config.py` → `REFERRAL` (every number printed on the pages)
- `netlify/lib/referral-config.mjs` → `REWARDS` (API responses, SMS text, CRM notes)

## How it works, end to end

1. **The owner texts a customer** the program link (the app's home page,
   e.g. `https://refer.bartawindowwashing.com/`): "Want $50 off? Refer a
   friend."
2. **The customer fills in the form**: their own name, phone, optional
   email, who they're referring (name + phone required; email, address, and
   a note optional; up to 10 friends at once), and which reward they want
   (credit or gift card). They confirm they have their friends' permission
   to share their contact details.
3. **The app stores the referral** (Netlify Blobs), **creates a lead in
   Rotor** for each friend (tag `Referral`, source `Referral program`,
   notes naming the referrer and the code), and, when SMS is enabled,
   **texts the friend, the referrer, and/or the office** (see
   `REFERRAL_SMS_MODE`). The customer sees a success screen with their
   share code, a copy-able share link, one-tap "Text a friend" / "Email"
   buttons, and a private tracking link.
4. **The office reaches out to the friend** ("Hi Jane, Alex referred you,
   here's $25 off") — either automatically via Twilio or manually from the
   admin dashboard, which has one-tap `sms:` links with the message
   pre-written.
5. **The friend claims the offer** on the short link `/r/CODE`: the page
   greets them by the referrer's name and has a short "Claim my $25 off"
   form (name, phone, optional email/address, what they're interested in).
   Submitting creates the quote request in Rotor with the referrer and code
   attached and moves the referral to *Quote requested*. Friends who were
   never listed but got the link from the customer are recorded on the spot
   under that customer, so they earn the reward too.
6. **The office marks the referral Booked, then issues the reward** in the
   admin dashboard (`$50 credit` or `$25 gift card`). The referrer's private
   tracking page updates immediately.

## Pages

| URL | Purpose | Indexed |
|-----|---------|---------|
| `/` | Program page: offer, how it works, the referral form, program terms. With `?t=TOKEN` it also shows the referrer's private dashboard (their referrals, statuses, rewards, share tools) and lets them add more friends. | yes |
| `/r/CODE` (serves `friend.html`) | Friend landing: "Alex sent you $25 off", the claim form, what Barta does, call button. Unknown code → generic version. | no |
| `/admin/` | Office dashboard, protected by `REFERRAL_ADMIN_KEY`. | no (`noindex` + `robots.txt` Disallow) |

The pages are generated by `python3 build.py` (run from the repo root) from
`build/pages.py`, `build/admin_page.py`, `build/chrome.py` and
`build/config.py`, into `public/`. Page styling and behaviour:
`public/assets/css/app.css` + `public/assets/js/app.js` (customer pages),
`public/assets/css/admin.css` + `public/assets/js/admin.js` (dashboard).
`public/assets/css/site.css` is a snapshot of the main website's stylesheet
(its design tokens and components) so the app looks like the brand; the
fonts are the same self-hosted files (ITF Free Font License, `assets/fonts/FFL.txt`).

## Deploying (Netlify, one-time)

1. Netlify → **Add new site → Import an existing project →** pick the GitHub
   repository and branch that hold this app (a repository of its own, or the
   `referral-app` branch of the `website` repository, where it lives on its
   own with nothing from the website).
2. Leave the build settings as Netlify detects them: it reads `netlify.toml`
   (build command `python3 build.py`, publish `public`, functions
   `netlify/functions`) and installs `@netlify/blobs` from `package.json`
   automatically.
3. **Environment variables** (Site configuration → Environment variables):

   | Variable | Required | Purpose |
   |----------|----------|---------|
   | `ROTOR_API_KEY` | yes | Creates referred friends and claims as leads in Rotor (Settings → Integrations in Rotor). |
   | `REFERRAL_ADMIN_KEY` | yes, for the dashboard | Long random secret (32+ chars, e.g. `openssl rand -base64 32`) the office enters on `/admin/`. Without it the admin API returns 503 and the dashboard says so. |
   | `REFERRAL_SMS_MODE` | no (default `off`) | `off` = no automatic texts (office texts manually from the dashboard). `office` = text the office number on every new referral. `all` = also text the friend and the referrer. |
   | `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` | only when SMS mode ≠ `off` | Twilio credentials; `TWILIO_FROM` is the sending number in E.164 (`+17633143400`) or a Messaging Service SID (`MG…`). |
   | `REFERRAL_OFFICE_PHONE` | only for SMS modes `office`/`all` | Where new-referral alerts are texted (E.164). |
   | `SITE_URL` | no | Base for links in texts and API responses. Defaults to Netlify's own `URL` for the site, so it only needs setting for previews. |

4. **Deploy.** You get a `*.netlify.app` URL immediately; add the real
   subdomain under **Domain settings** (a CNAME for `refer` at your DNS
   host), then set `APP_URL` in `build/config.py` to it and push so the
   canonical / link-preview URLs match.

Netlify Blobs needs no configuration; it is available to every Netlify
Function automatically and the data survives deploys. Nothing referral-
related works on a plain static host (no functions), where the forms show
the honest call-us fallback.

> **Texting referred friends.** Mode `all` sends a text to a person who has
> not themselves opted in, on the strength of their friend's confirmation
> that they have permission. Keep the message to a single informational
> text with an opt-out line (the templates below do), or leave the mode at
> `off`/`office` and text from the dashboard by hand. Have this reviewed
> against TCPA/CTIA guidance before turning `all` on.

## Data model (Netlify Blobs, store `referrals`)

All records are JSON. Timestamps are ISO-8601 UTC strings. Phone numbers
are stored both as typed (`phone`) and normalized to 10 digits
(`phone_digits`, US only, leading `1` stripped); the digits are the
identity everywhere.

```
referrer/{referrer_id}         referrer_id = phone_digits
  { id, code, token, first_name, last_name, phone, phone_digits, email,
    reward_pref: "credit" | "giftcard", consent_at, source_page,
    created_at, updated_at }

code/{CODE}                    -> { referrer_id }        public share code, e.g. BARTA-7K3XQ
token/{TOKEN}                  -> { referrer_id }        private dashboard token, 24 chars, base32

referral/{referral_id}         referral_id = "r_" + base36 time + 6 random chars
  { id, referrer_id, code, referrer_name, referrer_phone,
    first_name, last_name, phone, phone_digits, email, address, note,
    office_note,
    status: "new" | "contacted" | "quoted" | "booked" | "rewarded" | "declined",
    history: [ { status, at, by: "system" | "office" | "lead-form", note } ],
    reward: null | { type: "credit" | "giftcard", amount, issued_at, note },
    duplicate_of: null | referral_id,
    rotor: { delivered: bool, status: number | null, at },
    sms: { friend: bool, referrer: bool, office: bool },
    quote_requested_at: null | ISO,
    created_at, updated_at }

idx/referrer/{referrer_id}/{referral_id}  -> { id }     lists a referrer's referrals
idx/phone/{friend_phone_digits}            -> { id }     first referral of this friend (dedupe + claim matching)
```

Codes use the alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no 0/O/1/I),
five characters after the `BARTA-` prefix. Lookups are case-insensitive.

### Statuses

| Status | Meaning | Set by |
|--------|---------|--------|
| `new` | Referral received; office has not reached out yet. | system |
| `contacted` | Office has texted/called the friend. | office |
| `quoted` | The friend claimed the offer / requested a quote. | claim form (automatic) or office |
| `booked` | The friend booked/completed their first service; reward is owed. | office |
| `rewarded` | Reward issued to the referrer (`reward` filled in). | office (`issue_reward`) |
| `declined` | Not eligible / not interested / duplicate. | office |

The office can move a referral to any status at any time; `rewarded` is
set through `issue_reward` so the reward details are always recorded.

### Duplicates

A friend phone number that already has a referral (from anyone) is
accepted but flagged: the new record gets `duplicate_of` set to the first
referral's id and status `new`; it is **not** sent to Rotor again and no
friend text goes out. The referrer sees it as a normal "Sent" entry; the
office sees a "Duplicate" badge and decides. A referrer can never refer
their own phone number.

## API (Netlify Functions, same origin)

All responses are JSON with `Cache-Control: no-store`. Errors are
`{ "ok": false, "error": "<human readable>", "field": "<optional dotted path>" }`.
Every read endpoint answers `503` when Netlify Blobs itself is unavailable.

### `POST /api/referral` — submit referrals (public)

```json
{
  "referrer": { "first_name": "Alex", "last_name": "Barta", "phone": "(763) 555-0100",
                "email": "alex@example.com", "reward_pref": "credit" },
  "friends": [
    { "first_name": "Jane", "last_name": "Doe", "phone": "763-555-0101",
      "email": "", "address": "123 Main St, Delano, MN 55328", "note": "Neighbor, big house" }
  ],
  "consent": true,
  "page": "/",
  "token": "optional — when adding friends from an existing private dashboard"
}
```

Rules: referrer first name + valid 10-digit US phone required; `reward_pref`
required (`credit`/`giftcard`); `consent` must be `true`; 1–10 friends; each
friend needs a first name and a valid phone; a friend's phone can't equal
the referrer's; duplicates within one submission collapse to one. Field
caps: names 60, email 120, address 200, note 500 chars; longer values are
rejected with `400` and the field path.

Success `200`:

```json
{
  "ok": true,
  "code": "BARTA-7K3XQ",
  "token": "K7Q2M9X4P8W3N6R5T2Y7V4B9",
  "share_url": "https://refer.bartawindowwashing.com/r/BARTA-7K3XQ",
  "status_url": "https://refer.bartawindowwashing.com/?t=K7Q2M9X4P8W3N6R5T2Y7V4B9",
  "referrer": { "first_name": "Alex", "reward_pref": "credit" },
  "friends": [ { "id": "r_m1abc2xyz123", "first_name": "Jane", "status": "new", "duplicate": false } ],
  "stored": true,
  "delivered": true
}
```

`stored: false` means Netlify Blobs was unavailable (referrals still went to
Rotor; tracking link will not work). `delivered: false` means Rotor
rejected/was unreachable for at least one friend (they are still stored and
show in the dashboard). Only when **both** fail does the request return
`502` so the page shows the call-us fallback. An existing referrer (same
phone) keeps their existing code; `token` and `status_url` are only returned
for a **new** referrer or when the request carries the referrer's existing
`token` (they came from their tracking link). Otherwise both are `null` and
`returning: true`: the referrals are still accepted, but a phone number alone
never unlocks someone's private link or changes their reward choice. The
customer's original link keeps working, and the office can resend it from
the dashboard.

### `GET /api/referral?t=TOKEN` — private dashboard (referrer)

```json
{
  "ok": true,
  "referrer": { "first_name": "Alex", "last_name": "Barta", "phone": "(763) 555-0100",
                "email": "alex@example.com", "reward_pref": "credit", "code": "BARTA-7K3XQ" },
  "share_url": "https://refer.bartawindowwashing.com/r/BARTA-7K3XQ",
  "totals": { "referred": 3, "booked": 1, "rewarded": 1, "pending": 1,
              "credit_earned": 50, "gift_cards_earned": 0 },
  "referrals": [
    { "id": "r_…", "friend_name": "Jane D.", "status": "rewarded",
      "created_at": "…", "updated_at": "…",
      "reward": { "type": "credit", "amount": 50, "issued_at": "…" } }
  ]
}
```

`totals.pending` counts `new`/`contacted`/`quoted`; `booked` counts
`booked` + `rewarded`. Unknown token → `404`.

### `GET /api/referral?code=CODE` — public share-code lookup (friend page)

```json
{ "ok": true, "code": "BARTA-7K3XQ", "referrer_first_name": "Alex",
  "friend_discount": 25, "referrer_credit": 50, "referrer_gift_card": 25 }
```

Deliberately exposes only the referrer's first name. Unknown code → `404`.

### `POST /api/claim` — a referred friend claims the offer (public)

```json
{ "code": "BARTA-7K3XQ", "first_name": "Jane", "last_name": "Doe", "phone": "763-555-0101",
  "email": "", "address": "123 Main St, Delano", "services": ["Gutter Cleaning"],
  "note": "Best after 5pm", "consent": true, "page": "/r/BARTA-7K3XQ" }
```

First name, a valid phone and `consent: true` are required; `code` is
optional (a mistyped code is kept in the notes for the office). The claim
always becomes a Rotor lead (source `Referral program`, tag `Referral`,
`service_type` from the services, notes with the referral code and referrer,
the services and the friend's note). Then, by code and/or phone: a listed
friend's referral moves `new`/`contacted` → `quoted`; a friend nobody listed
gets a `quoted` record created under the referrer (`rotor.delivered`
reflects the CRM answer); a customer using their own code is not treated as
a referral (tag `Referral program`, note "not a referral"). Response:

```json
{ "ok": true, "code": "BARTA-7K3XQ", "referrer_first_name": "Alex", "delivered": true, "stored": true }
```

`code` is `null` when nobody referred them. `502` only when the CRM failed
**and** nothing could be recorded.

### Admin — `/api/referral/admin`

Every request carries `Authorization: Bearer <REFERRAL_ADMIN_KEY>`.
Wrong/missing key → `401`; key not configured on the server → `503`.

`GET /api/referral/admin` (optional `?status=new&q=jane`):

```json
{
  "ok": true,
  "stats": { "total": 12, "by_status": { "new": 3, "contacted": 2, "quoted": 1, "booked": 2, "rewarded": 3, "declined": 1 },
             "rewards_owed": 2, "credit_issued": 100, "gift_cards_issued": 1 },
  "referrals": [ { …full referral record… } ],
  "referrers": [ { "id": "7635550100", "code": "BARTA-7K3XQ", "first_name": "Alex", "last_name": "Barta",
                   "phone": "(763) 555-0100", "email": "…", "reward_pref": "credit", "created_at": "…",
                   "status_url": "https://refer.bartawindowwashing.com/?t=…",
                   "referred": 3, "booked": 1, "rewarded": 1 } ]
}
```

Newest referrals first. `?status=` and `?q=` narrow only `referrals`;
`stats` stay global and `referrers` is always the full list (each with a
ready-made `status_url` so the office can resend a customer's tracking
link; the raw token is never returned). `GET /api/referral/admin?format=csv`
returns `text/csv` (UTF-8 with a byte-order mark, so Excel opens it
correctly) of every referral (filters ignored, one row each) for a
spreadsheet; cells that start with `=`, `+`, `-` or `@` are neutralized so
a spreadsheet can't run them as formulas.

`POST /api/referral/admin` with one of:

```json
{ "action": "set_status",  "id": "r_…", "status": "contacted", "note": "Left voicemail" }
{ "action": "issue_reward", "id": "r_…", "reward_type": "credit", "note": "Applied in Rotor 9/3" }
{ "action": "set_note",     "id": "r_…", "note": "Office-only note" }
{ "action": "set_reward_pref", "referrer_id": "7635550100", "reward_pref": "giftcard" }
{ "action": "delete",       "id": "r_…" }
```

Each returns `{ "ok": true, "referral": {…} }` (or `{ "ok": true, "referrer": {…} }`,
or `{ "ok": true, "deleted": "r_…" }`). `issue_reward` sets `status:
"rewarded"` and `reward: { type, amount, issued_at, note }` (amount from
`REWARDS`; `reward_type` defaults to the referrer's `reward_pref`). Every
status change appends to `history` with `by: "office"`. Guard rails:
`issue_reward` on a referral that is already `rewarded` answers `409`;
`set_status` to `rewarded` answers `400` (rewards go through `issue_reward`);
moving a rewarded referral to another status clears its `reward`. Ids must
look like `r_…` and `referrer_id` must be a 10-digit phone; anything else is `404`.

## Text message templates

Used by the Twilio sender and, verbatim, by the dashboard's one-tap `sms:`
links (so manual and automatic texts read the same).

- **Friend:** `Hi {friend_first}! {referrer_first} {referrer_last_initial}. referred you to Barta Window Washing, so your first service is $25 off. Claim it here: {share_url} or call (763) 314-3400. Reply STOP to opt out.`
- **Referrer (confirmation):** `Thanks for referring {n} friend(s) to Barta Window Washing! You earn a $50 credit (or a $25 gift card) for each one who books. Track your referrals: {status_url}`
- **Referrer (reward issued, manual from dashboard):** `Great news from Barta Window Washing: {friend_first} booked, so your {reward} is ready. Thanks for spreading the word!`
- **Office alert:** `New referral: {referrer_name} ({referrer_phone}) referred {friend_name} ({friend_phone}). Code {code}. {site}/admin/`

When the referrer gave no last name the friend text reads `Alex referred
you…`. The customer's own "Text a friend" / "Email a friend" buttons send a
shorter personal note from their own phone (`Hi! Alex referred you to Barta
Window Washing, so your first service is $25 off. Claim it here: {share_url}`).

## Admin dashboard (`/admin/`)

Phone-friendly, app-like page. Enter the admin key once (kept in
`sessionStorage`). Shows: stat tiles (New, Contacted, Quote requested,
Booked / rewards owed, Rewards issued, credit and gift cards issued),
status filter tabs, a search box (name / phone / code), and a card per
referral with friend and referrer details, created date, status, a status
selector, "Text friend" / "Call friend" / "Text referrer" one-tap links, an
office note, and an **Issue reward** action ($50 credit or $25 gift card,
defaulting to the referrer's choice). A Referrers view lists each customer
with referred / booked / rewarded counts and their reward preference.
**Export CSV** downloads everything. A `401` sends you back to the key
screen. The dashboard is excluded from analytics and search engines.

## Launch checklist

1. Create the Netlify site from this repository, set `ROTOR_API_KEY` and
   `REFERRAL_ADMIN_KEY`, deploy.
2. Open `/admin/`, enter the key, confirm the empty dashboard loads.
3. Submit a test referral on `/` (use your own phone as the friend). Confirm
   it shows in the dashboard and as a lead tagged `Referral` in Rotor.
4. Open the short link from the success screen (`/r/CODE`) and claim it as
   the friend; confirm the referral shows *Quote requested* and the claim
   arrived in Rotor.
5. Open the tracking link; mark the referral Booked in the dashboard, then
   Issue reward; confirm the tracking page shows *Reward issued*.
6. Optional: add Twilio variables and set `REFERRAL_SMS_MODE=office` to get
   an alert text per referral; move to `all` only after the compliance note above.
7. Point the real subdomain at the site, set `APP_URL` in `build/config.py`,
   push, then text your customers the link.
